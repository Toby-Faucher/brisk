# Stack integration: Stage 1 to 6c together, with art

Branch `stack-all`, started from `stage6a-playtime` (which already holds emulator-launch, stage 1 and 6a). The four
sibling branches are merged on top, one at a time, so the whole set is checked as one tree. `stage3-art` is merged last.

## Merge order and conflicts

1. `stage2-ingest`: no conflicts.
2. `stage4-launch`:
   - `http.rs`: kept the ingest/upload handlers and the launch-option handlers, both route sets mounted.
   - `lib.rs`: both module lists (`ingest`, `uploads`, `launch`, `launchstore`, `wrap`).
   - `main.rs`: `add` and `wrap` both run before the server starts.
   - `docs/hosting-runbook.md`: "Adding games" and "Launch options" sections both kept.
   - `Emulators.svelte`, `registry.ts`, `registry.test.ts`: Dolphin shows Controllers, Launch options and Games folders (neither is "planned" any more).
   - `api.ts`: upload/scan types and launch types both exported.
3. `stage5-achievements`: only `GameDetail.browser.test.ts` conflicted; both describe blocks kept.
4. `stage6c-saves`:
   - `docs/env.md`: both env rows kept.
   - `GameDetail.svelte`: imports unioned (`RaAnswer` and `GameSaves`, `saveRow`); the Saves section sits before Achievements.
5. `stage3-art` (also brings the SteamGridDB and GameTDB branches). One line each:
   - `emu.rs`: `emu::caps` sets `art: true` next to `launch_options: true`.
   - `http.rs`: `AppState` holds both `ra_refresh` and `art`; the router mounts the `/art/...` and `/games/{id}/art/{kind}` routes next to the launch, saves and RetroAchievements ones.
   - `steam.rs`: kept `https_get` as `pub(crate)` and added the art branch's `get_limited` (bearer token, own body cap).
   - `docs/hosting-runbook.md`: the "Art and details" section sits after "Launch options".
   - `Emulators.svelte`, `registry.test.ts`: Dolphin shows Controllers, Launch options, Games folders and Art and details.

`caps.launchOptions`, `caps.achievements` and `caps.saves` are each set in one place (`emu::caps`, `ra_game`, `emu::games`), so they compose. `caps.art` is set in `emu::caps`.

## Cross-feature fix

Stage 2's scan keeps an older record's slug id (`emu:dolphin:mario-kart-wii`) and stores the disc id as an alias
(`emu:dolphin:RMCE01`). The saves route only looked at the id tail, so it found nothing for those games.
`emu::disc_id_of(&Record)` now returns the first 6-character alphanumeric tail among the record's `id` and `aliases`;
`GET /api/games/{id}/saves` uses it. Stage 3 (art) and anything else that wants a disc id should call it too.
The art pipeline derived one too: the GameTDB lookup took the id tail, so a slug-id game got no details. It now takes
the disc id from `emu::disc_id_of` (new unit test `gametdb_uses_the_disc_id_not_a_slug_id`). Art files are keyed by the
record id, and names come from the library title, so Find art works for a slug id.

- New test `saves_route_finds_the_disc_id_in_an_alias` (slug id plus alias `emu:dolphin:RMCE01` lists the RMCE01 save states).

Not verified: nothing deployed, nothing seen rendered, no real emulator, pad, RetroAchievements, SteamGridDB or GameTDB run (art was checked against loopback mocks only).

## Final feature list

Emulator ingest and uploads, launch options (MangoHud, GameMode, gamescope, env, custom command), RetroAchievements,
playtime, save states, and art and details (SteamGridDB art, optional GameTDB details), all on top of emulator-launch.

## How to merge

Recommended: merge draft PR 13 instead of PRs 7 to 12 and 14, one by one: they share `game.rs`, `http.rs`, `lib.rs`, `steam.rs`, `api.ts`,
`GameDetail.svelte` and the docs, so merging them in sequence conflicts again at each step. This branch already holds
the resolutions. Merge it after `emulator-launch` (PR 5) is in; it already includes Stage 3. The individual PRs
stay useful for reading one stage at a time.
