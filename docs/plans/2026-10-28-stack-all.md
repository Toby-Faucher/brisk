## Cross-feature fix

Stage 2's scan keeps an older record's slug id (`emu:dolphin:mario-kart-wii`) and stores the disc id as an alias
(`emu:dolphin:RMCE01`). The saves route only looked at the id tail, so it found nothing for those games.
`emu::disc_id_of(&Record)` now returns the first 6-character alphanumeric tail among the record's `id` and `aliases`;
`GET /api/games/{id}/saves` uses it. Stage 3 (art) and anything else that wants a disc id should call it too.
The art pipeline derived one too: the GameTDB lookup took the id tail, so a slug-id game got no details. It now takes
the disc id from `emu::disc_id_of` (new unit test `gametdb_uses_the_disc_id_not_a_slug_id`). Art files are keyed by the
record id, and names come from the library title, so Find art works for a slug id.

## Review findings

An independent review found no critical or high problems. Fixed on this branch:

- Custom commands: `MANGOHUD_CONFIG` left the env list (MangoHud's config has an `exec=` key that runs a command, which
  would bypass the Allow custom commands switch). The runbook and the Settings Launch tab now say the switch is a catch
  against mistakes, not a security boundary, and that extra arguments are appended to the game or emulator command as given.
- Uploads: a move falls back to a copy when the file system refuses hard links (exFAT, FAT, some network mounts).
- Scans: each path is resolved once, not once per record pair; game removal no longer blocks a runtime worker; the
  library file is re-read only when it changed.
- Art: a refresh keeps the old cache until new art arrives; a refused key or rate limit pauses the queue for 10 minutes.
- GameTDB: a failed database download is remembered for an hour, the parsed index stays in memory, and the download
  has its own 5 minute limit.
- Low: library.json gets a one-time `.bad-<time>` copy before records that did not parse are dropped; a damaged
  removed.json is moved aside and the scan refuses to run (so removed games do not come back); the playtime poll is
  capped at 15 s with saturating math and the scan and save run off the async workers; RetroAchievements date math is
  checked; header-less ROMs upload into their system folder; a failed finish frees its upload slot and cancel stops a
  chunk in flight; the hub proxy passes `Retry-After`; FIFOs are refused without blocking and the MD5 table is computed
  once; `/api/ids/remap` on a machine with a library only moves to known games and skips numbers two games share (the
  web client also skips a shared number); art `?v=` and ETag use nanoseconds.

Not fixed:

- Owner-set base URLs (`BRISK_SGDB_BASE`, `BRISK_RA_BASE`, `BRISK_GAMETDB_*`) can point a client at any https host. They
  are set by the machine's owner. The web client's `localStorage` copy of the secret is older than this branch.
- `extra_args` are not gated by the custom command switch (documented, see above).
- An art refresh that is interrupted by a crash leaves `art/<key>.old` behind with no cache for that game.
