# Brisk M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chrome on Toby's laptop shows bawn's desktop at 1080p60 H.264 with audio, mouse and keyboard, with the Sunshine tap plus bridge adding at most 2 ms median over the host encode.

**Architecture:** A ~60-line patch to Sunshine sends each encoded frame (Annex B) to a unix SEQPACKET socket owned by the bridge instead of RTP/FEC/AES. A new `brisk-bridge` crate (built on `brisk-client`) speaks Moonlight to Sunshine (M1), receives tap frames, and forwards video as WebTransport unidirectional streams and Opus as datagrams. The page decodes with WebCodecs and sends input back.

**Tech Stack:** Rust (M1 crates), tokio, a QUIC/WebTransport crate (`wtransport` or `web-transport-quinn` [U, pick in Task 4 spike]), Sunshine v2026.914.233613 + C++ patch, Astro + Svelte (minimal shell only), Chrome WebCodecs/WebTransport.

**Spec:** `docs/design.md` (sections 4, 7, 10 M2 row, 11), `research/m2-tap-design.md` (tap point, framing, install, risks), `docs/m1-notes.md`, `docs/moonlight-compare.md`.

## Global Constraints

1. Decisions (Toby, 2026-10-24): side-by-side install in `~/.local/opt/sunshine-brisk` plus a user-unit drop-in (not a package swap); tap missing means Sunshine falls back to normal RTP; M2 is H.264 only (HEVC later); on a full tap socket Sunshine drops the frame and self-requests an IDR; downloads of Boost, FFmpeg and npm packages at build time are allowed.
2. Pure Rust in the product; the only C++ is `patches/sunshine/0001-brisk-tap.patch` (about 60 lines, 3 files).
3. 1080p60, 8-bit SDR, stereo audio. Chrome only. Mouse and keyboard only (controller is M3).
4. M2 gate (design.md section 10): 10 min at 1080p60 with 0 decode errors; `bridge_write - capture` p50 <= `frame_processing_latency` p50 + 2 ms.
5. Root only via `sudoq run --why "..." -- cmd`; the only expected root step is one `setcap` per reinstall. Exit 77 = stop and ask Toby; exit 75 = tell Toby. Never touch bond0, NetworkManager or disk layout.
6. Build Sunshine from a fresh clone of tag `v2026.914.233613` plus the patch in `~/build/sunshine-brisk`, never from `~/recon-pinned` (empty submodules, read-only reference).
7. Rollback must always work: remove `brisk.conf` drop-in, `daemon-reload`, restart. Verify it in Task 2. Stock `sunshine-bin` stays installed. Keep `~/.config/sunshine` shared so pairings survive.
8. Sunshine `min_log_level = verbose` stays on (Toby's choice). Never commit raw Sunshine logs (they hold keys and cookies).
9. Anything unverified is tagged `[U]` in code comments and docs; no latency claim without a number. Reuse `brisk-proto` sans-io style: parsers take bytes, no sockets or clocks.
10. Never launch, cancel or take over a session you did not start; the M1 safety rules (`--take-over`, ambiguous-launch rule) apply to the bridge.
11. Branch `m2` from `m0-m1` head. Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Bridge dies mid-stream: Sunshine gets `EPIPE`, stops the session, and the app is not left half-owned; restarting the bridge starts clean with a fresh rikey (final-fix-list item 4).
2. Slow browser (decode or network): old streams are reset, frames dropped until the next IDR, IDR requested at most once per 100 ms; no unbounded memory growth in the bridge.
3. Tap socket full or a huge frame (IDR of several hundred KB): the encoder thread never blocks; `dropped` counters appear in the header and the page stats.
4. Chrome autoplay and tab backgrounding: audio starts only after the connect click; a hidden tab neither crashes the bridge nor builds a queue.
5. Malformed tap or WebTransport input (bad magic, `header_len` too small, absurd lengths, unknown input event): rejected with an error, no panic, capped at 4 MiB per frame.
